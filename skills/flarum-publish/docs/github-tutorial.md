# 从 GitHub 项目生成使用教程（回帖形式）

> 本功能为**可选项**，仅在发布项目文章之后、由用户以关键词明确触发时使用，不随发布流程自动执行。

用户在某个项目文章已发布后，要求「整理教程」「生成使用教程」并回帖时，按本文流程执行：

1. 以 GitHub 项目信息整理一篇**基础使用教程**（临时文件，默认 `/tmp/tutorial.md`）；
2. 以**回帖**形式发布到该项目**之前已创建的讨论**下。

## 触发条件

- 用户主动使用关键词触发（如「整理教程」「生成教程」「写个使用教程回帖」），agent 不得在发布完成后主动询问或自动执行。
- 目标讨论必须是本 skill 之前已创建的该项目文章；找不到对应讨论时向用户询问讨论 ID 或链接。

## 教程内容要求

素材来源与文章一致（仓库元数据 + README），但定位是**使用教程**，与项目宣传文章区分：

- **只写上手与使用相关内容**：安装、依赖准备、快速开始、基本用法、常用命令/配置、进阶用法，酌情补充常见问题（FAQ）。
- **排除与教程无关的描述**：捐赠/赞助（donate、sponsor、patron、爱发电等）、stars/forks 等社交数据、徽章、发展历史、贡献指南、社区宣传、 Roadmap、许可讨论等一律不写入教程。
- 结构建议（按需裁剪，没有的小节跳过）：
  - `# <项目名> 使用教程`（一级标题；回帖正文可不带一级标题，带时格式如下）
  - `## 安装`：安装方式与依赖（包管理器、二进制下载、Docker、源码编译等，按 README 实际内容）
  - `## 快速开始`：最小可运行示例，含代码块（保留原始命令，注释用中文）
  - `## 常用用法`：核心命令、配置说明、典型场景，代码块 + 中文说明
  - `## 进阶`：可选，进阶配置或组合用法
  - `## 常见问题`：可选，README 中能提取到的 FAQ
- 全文简体中文，专有名词、命令、路径保留英文原文；命令必须来自 README/文档原文，**不要臆造命令或参数**。
- **回帖中引用主帖（或站内其他讨论）时，链接一律用站内内链形式**：不补全论坛 URL，直接写 `[TITLE](/d/<POST_ID>)`，如 `[Firemark：开源的图片/PDF 水印工具](/d/1234)`；不要写成 `[TITLE](https://forum.example.com/d/1234)` 这类绝对地址。
- 教程是临时产物，保存到 `/tmp`（如 `/tmp/tutorial.md`），不落入 skill 目录。

## 回帖流程

1. **确定目标讨论**：从会话上下文找之前发布该项目时记录的讨论 ID / 链接（`$FLARUM_URL/d/<id>`）；找不到时询问用户。
2. **整理教程**：按上文要求生成 `/tmp/tutorial.md`，在对话中向用户展示教程全文供确认。
3. **确认**：这是对外可见的公开操作，必须经用户确认后才回帖。
4. **回帖**：调用 `scripts/reply.py`：

   ```bash
   "$SKILL_PATH/scripts/reply.py" <discussion_id> /tmp/tutorial.md
   # 或正文从 stdin 读入
   cat /tmp/tutorial.md | "$SKILL_PATH/scripts/reply.py" <discussion_id> -
   ```

5. **验证**：脚本输出回帖成功信息与讨论链接，向用户报告。

回帖不涉及标签与标题；教程回帖不需要查重（目标讨论已存在）。
